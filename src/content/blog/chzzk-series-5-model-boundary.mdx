챕터를 나누고 제목을 붙이는 일을 언어 모델 하나에 통째로 맡기지 않았다. 후보를 만들고 결과를 확정하는 일은 코드가 하고, 모델은 그 사이에서 코드가 묻는 질문에만 답한다. 챕터 경계 단계에서는 이웃한 두 후보가 같은 챕터로 이어지는지를 판정하고, 제목 단계에서는 제목으로 쓸 이름 후보를 돌려준다.

## 모델 없이 만드는 후보

먼저 전사문을 2분씩 잘라 KURE-v1로 임베딩하고, 내용이 비슷한 조각끼리 이어 붙여 챕터 후보를 만든다. 이 단계에서는 언어 모델을 한 번도 부르지 않는다.

## 예·아니오로 받는 판정

경계 판정에서는 이웃한 후보 두 개의 원문을 모델에 보여 주고, 두 후보가 같은 챕터로 이어지는지 묻는다. 모델은 판정 이유를 먼저 적고, 이어지는지를 예 또는 아니오로 답한다. 화제 이름이나 요약, 확신도 같은 다른 값은 받지 않는다. 후보를 화제 이름으로 줄여서 보여 주면 한 코너가 여러 화제로 쪼개져 보여서, 원문을 통째로 보여 준다.

```json
{
  "properties": {
    "why": { "type": "string" },
    "carries_on": { "type": "boolean" }
  },
  "required": ["why", "carries_on"]
}
```

이 판정에서 앞뒤 어느 쪽과도 이어지지 않은 180초 미만의 짧은 후보에 대해서는 한 번 더 묻는다. 이번에는 앞 후보, 짧은 후보, 뒤 후보의 원문을 함께 보여 주고, 짧은 후보가 화제에서 잠깐 벗어난 곁길인지와 뒤 후보가 앞 후보의 화제로 돌아오는지를 각각 예·아니오로 묻는다. 이 판정에서는 이유를 판정 뒤에 한 줄로 받는다.

```json
{
  "properties": {
    "carries_on_prev": { "type": "boolean" },
    "detour": { "type": "boolean" },
    "why": { "type": "string" }
  },
  "required": ["carries_on_prev", "detour", "why"]
}
```

곁길로 판정되면 세 후보가 한 챕터로 합쳐져, 그 사이의 경계 두 개가 없어진다. 운영한 방송 13개 가운데 6개에서 곁길 판정이 10건 나왔고, 경계 20개가 없어졌다. 판정 결과를 모아 경계를 확정하는 일은 다시 코드가 한다.

## 코드가 고르는 제목

제목 단계에서는 챕터 전사문을 모델에 직접 읽혀, 제목 후보가 될 이름들과 각각의 시작 시각, 그리고 각 이름이 챕터에서 차지하는 비중을 추정한 값을 돌려받는다. 처음에는 챕터의 화제 이름을 다듬어 제목을 만들었는데, 이 방식은 전사문에 없는 내용을 만들어 냈다. 그래서 모델은 제목 문구를 짓지 않고 이름 후보만 돌려주게 했다.

모델이 돌려준 비중 추정값은 후보가 많으면 믿기 어려워서 쓰지 않는다. 대신 코드가 챕터를 30초씩 나누고, 30초 조각마다 KURE-v1 임베딩으로 어느 이름에 속하는지 다시 배정해 비중을 직접 잰다. 같은 화제를 여러 이름으로 부른 경우는 글자로는 합칠 수 없어서, 이름도 임베딩으로 비교해 미리 합친다. 비중이 가장 큰 이름이 50% 이상이면 그 이름 하나를 제목으로 쓰고, 그렇지 않으면 비중이 10% 이상인 이름을 최대 5개까지 고른다. 이름을 고르는 과정에는 언어 모델을 부르지 않는다.

## 사고 모드 대신 이유 칸

경계 판정의 이유는 모델의 사고 모드에 맡기지 않고, 답 안의 이유 칸에 적게 했다. 사고 모드는 모델이 답하기 전에 따로 생각을 길게 적는 기능이다. 같은 35쌍을 판정할 때 사고 모드를 켜면 164.8초가 걸렸고, 끄면 23.1초가 걸렸다. 사고 모드를 끄자 따로 생성하던 사고 글자 71,173자도 0자가 되었다.

사고 모드를 켠 채 사고의 양만 제한하는 방법도 시험했다. 반복을 억제하는 기능 없이 사고 예산만 13,000토큰으로 걸어 보니, 예산에 닿은 호출은 한 건도 없었고 같은 말을 끝없이 되풀이하는 폭주 5건도 그대로였다. 되풀이를 잡아내는 감시 장치가 예산보다 먼저 폭주를 잡아냈기 때문이다.

그래서 사고 모드를 껐고, 사고 모드를 끈 자리는 이유 칸으로 채웠다. 사고 모드의 생각과 달리, 이유 칸에 적은 내용은 판정과 함께 답에 남는다. 이유 칸은 답의 일부라서 이유를 적게 하면 답이 길어지므로, 이유 칸을 넣으면서 경계 판정 답의 최대 길이를 400자에서 1,200자로 늘렸다.
