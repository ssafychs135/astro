라이브방송 다시보기는 몇 시간씩 이어져서, 원하는 대목을 찾으려면 영상을 넘겨 가며 봐야 한다. 이 파이프라인은 방송 하나를 받아 챕터 목록을 만든다. 챕터마다 시작 시각, 길이, 제목이 붙는다. 모델 다섯을 모두 자체 호스팅해 16GB GPU 한 장에서 실행하고, 외부 API는 쓰지 않는다.

## 결과물

아래 목록은 10.5시간짜리 방송 하나의 뒷부분에서 연속한 다섯 줄을, 빼거나 고치지 않고 그대로 옮긴 것이다. 가운데 줄은 화면 판정이 게임 구간으로 판정해 챕터를 만들지 않은 부분이다.

|---|---|---|
| 7:25:51 | 6.2분 | 리샤인 |
| | 132.6분 | 게임 (챕터 대상에서 제외) |

| 10:20:15 | 2.2분 | 총기 종류 (글록, MPX, AKV) |
| 10:26:45 | 5.2분 | 총기 청소 게임 |

## 일곱 단계

방송은 수집, 화면 판정, 오디오 정리, 전사, 잇기, 챕터 경계, 제목의 일곱 단계를 차례로 거친다. 화면 판정은 게임 구간을 걷어내고, 오디오 정리는 노래와 말 없는 자리를 걷어낸다. 남은 소리는 긴 구간 몇 개로 나눠 구간마다 전사한다. 잇기 단계에서 구간마다 따로 나온 전사문을 방송 하나로 연결한 뒤, 챕터 경계를 판정하고 제목을 붙인다.

## 모델과 GPU

| 단계 | 모델 |
|---|---|
| 화면 판정 | SigLIP2 임베딩과 선형 분류기 |
| 오디오 정리 | AST |
| 전사 | faster-whisper large-v3-turbo (CTranslate2) |
| 챕터 경계, 제목 | Gemma 4 26B (llama.cpp), KURE-v1 |

GPU는 RTX 5060 Ti 16GB 한 장이다. 화면 판정, 오디오 정리, 전사 단계는 GPU를 비운 뒤 그 단계의 모델만 올려 실행한다. 챕터 경계와 제목 단계에서는 26B 언어 모델 서버와 KURE-v1 임베딩 서버를 함께 올려 둔다. 단계를 잇는 조율 서버는 Python과 FastAPI로 만들었다.
