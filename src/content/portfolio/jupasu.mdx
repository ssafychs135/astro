<Section n="01" label="Overview">

와인 라벨과 메뉴판을 스캔해 정보를 제공하고 취향 기반으로 추천하는 서비스입니다.

팀 프로젝트에서 **LLM·RAG·OCR AI 파이프라인을 설계하고 구현**하는 역할을 담당했습니다.

프로젝트가 끝난 뒤(2026.06)에는 개인 사본에서 LLM을 로컬 Gemma로 바꿔 LM Studio에서 실행했고, 아래 트러블슈팅 세 건은 이 개인 사본에서 진행한 작업입니다.

</Section>

<Section n="04" label="Defects">

프로젝트 종료 후 개인 사본(2026.06)에서 해결한 세 건입니다. 읽기 경로의 문제 한 건과, LLM을 로컬 Gemma로 바꾼 뒤 드러난 LLM 정제 단계의 문제 두 건입니다.

  <Grid
    cols={3}
    items={[
      { icon: '🐢', n: 'DEFECT 01', title: '느린 기동', sub: '읽기마다 임베딩 전체 로드 → 임베딩 제외 projection' },
      { icon: '🌀', n: 'DEFECT 02', title: 'LLM 환각', sub: '입력에 없는 와인 이름을 덧붙이는 충실성 문제' },
      { icon: '🧱', n: 'DEFECT 03', title: '구조화 출력', sub: '기본 방식의 빈 결과 → json_schema' },
    ]}
  />

  <Defect pnum="DEFECT 01" category="Read Path · 종료 후 개인 사본(2026.06)" title="읽기마다 임베딩 벡터를 통째로 로드하다">
    <div slot="summary">
      서버를 띄울 때와 첫 조회가 느리고, 임베딩 벡터가 메모리에 통째로 상주했습니다. 와인을 읽을 때 <b>추천 계산에 쓰지 않는 임베딩 벡터까지 항상 함께 불러온 것</b>이 원인입니다.
    </div>
    <ul slot="tech">
      <li>엔티티에 임베딩이 묶여 있어 목록과 검색에도 전부 로드됐다.</li>
      <li>수천 건의 고차원 벡터를 매번 파싱하고, 캐시에도 임베딩 포함 엔티티가 그대로 적재됐다.</li>
      <li><b>해결</b>: 스코어링용 조회를 임베딩을 뺀 경량 뷰로 분리했다: <code>List&lt;WineScoreView&gt; findAllScoreViews()</code>.</li>
      <li>추천 계산은 인터페이스로 받아 엔티티와 뷰를 함께 처리하고, 벡터는 유사도 검색이 필요할 때만 로드했다.</li>
    </ul>

    <Toggle heading="와인 목록·스코어링 조회 시" labelOff="엔티티 전체 로드" labelOn="임베딩 제외 projection">
      <div slot="off">
        <Verdict type="fail">읽기 경로에 임베딩까지 전부 로드</Verdict>
        <Kv k="조회" v="Wine 전체 (임베딩 포함)" type="fail" />
        <Kv k="캐시" v="18.66MB" type="fail" />
      </div>
      <div slot="on">
        <Verdict type="ok">필요한 컬럼만 조회</Verdict>
        <Kv k="조회" v="WineScoreView (임베딩 제외)" type="ok" />
        <Kv k="캐시" v="1.36MB" type="ok" />
      </div>
    </Toggle>
  </Defect>

  <Defect pnum="DEFECT 02" category="LLM Fidelity · 종료 후 개인 사본(2026.06)" title="입력에 없는 와인 이름을 덧붙이다">
    <div slot="summary">
      OCR 결과를 정리하는 LLM 정제 단계가 <b>입력에 없던</b> 와인 이름을 덧붙였습니다. 개인 사본에서 LLM을 로컬 Gemma로 바꾼 뒤 드러난 문제입니다.
    </div>
    <ul slot="tech">
      <li>원인 1: 지시문이 "정확한 와이너리, 와인 이름, 빈티지를 추론하세요"로 자유 생성을 허용했다.</li>
      <li>원인 2: 예시가 보르도 쪽으로 치우쳐 있었다.</li>
      <li>실패: 너무 강한 부정 명령은 모든 필드를 빈 문자열로 만들었다.</li>
      <li><b>해결</b>: 추론 지시를 입력에서 추출하는 지시로 바꾸고(빈티지는 입력에 보이는 4자리 연도만), 예시를 독일·프랑스·이탈리아 와인과 빈티지가 없는 경우로 다양화했다.</li>
    </ul>

    <Toggle heading={'같은 라벨 입력의 실제 출력 한 건: "JAKOB SCHNEIDER Niederhäuser…"'} labelOff="추론 지시·치우친 예시" labelOn="추출 지시·다양한 예시">
      <div slot="off">
        <Verdict type="fail">입력에 없는 와인을 출력</Verdict>
        <Kv k="와인" v="Chateau Lafite Rothschild" type="fail" />
        <Kv k="산지" v="Pauillac" type="fail" />
        <Kv k="빈티지" v="2015" type="fail" />
      </div>
      <div slot="on">
        <Verdict type="ok">입력에 있는 이름만 출력</Verdict>
        <Kv k="와인" v="Jakob Schneider · Niederhäuser Felsensteyer" type="ok" />
        <Kv k="빈티지" v="(빈칸)" type="ok" />
      </div>
    </Toggle>
  </Defect>

  <Defect pnum="DEFECT 03" category="Structured Output · 종료 후 개인 사본(2026.06)" title="구조화 출력이 빈 응답으로 돌아오다">
    <div slot="summary">
      구조화 출력으로 와인 정보를 요청하면 빈 결과가 돌아왔습니다. <b>기본 구조화 출력 방식(function calling)이 빈 결과를 자주 돌려줬고</b>, 실행 환경(LM Studio)은 JSON 모드를 지원하지 않았습니다.
    </div>
    <ul slot="tech">
      <li>LM Studio는 JSON 모드 요청에 <code>response_format.type must be json_schema or text</code> 오류를 돌려줬다.</li>
      <li>두 단어가 공백 없이 이어진 OCR 결과(붙은 단어)를 작은 모델이 풀지 못해 빈 응답을 만드는 경우도 있었다.</li>
      <li><b>해결</b>: <code>with_structured_output(WineInfo, method="json_schema")</code>로 형식을 명시했다.</li>
      <li><b>해결</b>: LLM을 호출하기 전에 붙은 단어를 나누는 전처리를 넣었다.</li>
    </ul>

    <Toggle heading="구조화 출력 요청 결과" labelOff="기본 방식(function calling)" labelOn="json_schema + 붙은 단어 분리">
      <div slot="off">
        <Verdict type="fail">빈 결과가 자주 돌아옴</Verdict>
        <div class="ts-io"><span class="ts-bad">{'{ }'}</span> 모든 필드 빈 값</div>
      </div>
      <div slot="on">
        <Verdict type="ok">필요한 항목을 모두 채움</Verdict>
        <div class="ts-io"><span class="ts-good">{'{ name, region, vintage, grape }'}</span></div>
      </div>
    </Toggle>
  </Defect>
