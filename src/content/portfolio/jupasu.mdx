<Section n="01" label="Overview">

위스키는 어느 정도 대중화됐지만 와인은 정보 진입장벽이 높습니다. 주파수는 와인 선택 실패 경험을 보완하는 **개인화 추천 PWA**입니다.

6인 팀(인프라 1, 백엔드 3, AI 2)에서 **LLM·RAG·OCR 파이프라인을 설계하고 구현**했습니다. 팀원들이 AI 개발을 경험하도록 업무를 나누고 안내했습니다.

</Section>

<Section n="04" label="Defects">

온디바이스 OCR(PaddleOCR)로 라벨을 읽고 LLM으로 정제하는 파이프라인에서, 작은 모델·게이트웨이·읽기 경로가 일으킨 현실 문제 네 건을 해결했습니다. 각 항목은 토글과 선택으로 직접 비교할 수 있습니다.

      { icon: '🌀', n: 'DEFECT 02', title: 'LLM 환각', sub: '입력에 없는 와인을 생성하는 충실성 문제' },

  <Defect pnum="DEFECT 02" category="LLM Fidelity" title="입력에 없는 와인을 만들어내다">
    <div slot="summary">
      OCR이 추출한 텍스트를 LLM 정제 단계에 넣으면 <b>입력에 없던</b> 와인을 반환했습니다. 작은 모델(Gemma 4B)에서는 프롬프트 설계가 곧 입력 충실성을 좌우했습니다.
    </div>
    <ul slot="tech">

      <li>원인 2: 퓨샷 예시가 보르도에 편향되어 모델이 예시를 그대로 복사했다.</li>
      <li>실패: 너무 강한 부정 명령은 모든 필드를 빈 문자열로 만들었다.</li>
      <li><b>해결</b>: 명령 톤을 완화하고 퓨샷 예시를 4개국으로 다양화하며 분류 기준을 제시했다.</li>
    </ul>

  <Defect pnum="DEFECT 04" category="Read Path" title="읽기마다 임베딩 벡터를 통째로 로드하다">
    <div slot="summary">
      서버를 띄울 때와 첫 조회가 느리고, 임베딩 벡터가 메모리에 통째로 상주했습니다. 와인을 읽을 때 <b>추천 계산에 쓰지 않는 임베딩 벡터까지 항상 함께 불러온 것</b>이 원인입니다.
    </div>
    <ul slot="tech">
      <li>엔티티에 임베딩이 묶여 있어 목록과 검색에도 전부 로드됐다.</li>
      <li>수천 건의 고차원 벡터를 매번 파싱하고, 캐시에도 임베딩 포함 엔티티가 그대로 적재됐다.</li>
      <li><b>해결</b>: 스코어링용 조회를 임베딩을 뺀 경량 뷰로 분리했다 — <code>List&lt;WineScoreView&gt; findAllScoreViews()</code>.</li>
      <li>추천 계산은 인터페이스로 받아 엔티티와 뷰를 함께 처리하고, 벡터는 유사도 검색이 필요할 때만 로드했다.</li>
    </ul>
