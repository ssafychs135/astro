<Section n="01" label="Overview">

국내 익명 커뮤니티 게시판에 올라올 법한 제목을 생성하는 모델을 만들었습니다. 처음에는 조회수가 높은 제목을 생성하는 것을 목표로 삼았습니다. 그러나 수집한 데이터를 분석해 보니 제목의 키워드가 참여도를 설명하는 정도는 댓글 기준 5.5%, 조회 기준 4.8%, 추천 기준 3.9%였습니다. 표본을 1만 건에서 8만 건으로 늘려도 값은 달라지지 않았습니다.

그래서 목표를 "그 게시판의 말투로 문장이 성립하는 제목을 생성하는 것"으로 다시 정했습니다. 목표에서 수치를 뺐기 때문에, 문장을 읽어서 판정하는 평가 체계를 설계하는 일이 프로젝트의 핵심 과제가 되었습니다.

2026년 9월 2일부터 12일까지 11일 동안 수집, 학습, 평가를 진행했습니다. 개념과 학습 과정은 블로그 연재 <a href={`${blog}/small-llm-finetuning-01-concepts/`}>1편: 개념 정리</a>, <a href={`${blog}/small-llm-finetuning-02-lora/`}>2편: LoRA 학습</a>, <a href={`${blog}/small-llm-finetuning-03-dpo/`}>3편: DPO 세 번</a>에 적었습니다.

</Section>

**데이터 수집과 구축.** 목록 페이지만 순회하는 수집기를 구현해 약 8만 건을 확보했습니다. 상세 페이지를 여는 방식과 비교하면 요청 비용이 41분의 1이었습니다. 작성자를 식별할 수 있는 값은 저장하지 않았습니다. 후보 키워드 383개는 다항 순열검정으로 231개까지 줄였습니다. 일시적인 사건 때문에 특정 날짜에 몰린 키워드를 고정된 임계값 대신 통계 검정으로 걸러 냈고, 남은 키워드의 밀도는 추천 상위 글에서 2.22~2.66배 높았습니다. 이 데이터로 약 3만 9천 행의 학습 데이터와 선호쌍 데이터 여러 판본을 구축했습니다.

**학습.** 기반 모델은 Gemma 4 계열의 E2B와 E4B를 같은 데이터로 학습해 비교한 뒤 E2B로 정했습니다. E4B는 문장 완성도가 높았지만, 초기 데이터로 학습한 두 모델에 같은 지시문을 주었을 때 은어와 자극 표현이 50건 중 14건에서 8건으로 줄었습니다. 목표가 유창성이 아니라 게시판의 말투였으므로 E2B를 기준으로 삼았습니다. 학습은 4bit QLoRA로 진행했고 어댑터의 rank는 32에서 64로 올렸습니다. DoRA는 2.85배 느린 반면 손실이 개선되지 않아서 사용하지 않았습니다. 학습에는 16GB GPU 한 장을 썼습니다.

**평가 체계.** 두 모델의 출력을 1,056건씩 준비해 고정된 시드로 섞고, 어느 쪽이 어느 모델인지 기록한 키는 별도의 파일로 보관했습니다. 표시를 모두 마친 뒤에 가림을 해제했습니다. 판정 기준은 문서로 고정했고, 존재하지 않는 낱말로 의심되는 것은 수집한 원문 제목 8만 건을 문자열로 검색해 실제로 쓰이는 말인지 확인했습니다.

**반복 속도.** 학습 표본의 평균 51토큰 중 38토큰이 반복되는 지시문이고, 배치에서 패딩이 23%를 차지한다는 것을 측정했습니다. 이를 바탕으로 지시문 길이와 배치 구성과 그래디언트 체크포인트를 조정해 스텝당 시간을 1.128초에서 0.539초로 줄였습니다. DPO에서도 배치 구성을 바꾸어 스텝당 3.55초를 1.47초로 줄였고, 참조 모델의 로그확률을 미리 계산했습니다. 학습, 생성, 평가를 한 바퀴 도는 시간은 38분에서 11분이 되었습니다.

<Section n="03" label="Result">

시도마다 결과를 판독과 측정으로 확정했습니다.

| 시도 | 결과 |
|---|---|
| 조회수와 추천수 상위 글을 복제하여 학습 | 평가 손실이 3.577로 기준 모델의 3.493보다 높았습니다. |
| 조건부 지시문 학습 | 같은 모델에서 지시문만 바꾸어 은어와 자극 표현을 50건 중 1건에서 28건까지 조절했습니다. |
| 직전 글을 맥락으로 주입 | 손실이 0.10 nat 내려간 것이 전부여서 폐기했습니다. |
| 샘플링 설정 조정 | 온도 1.0에서 깨진 문장은 top_p 0.9일 때 6.9%, top_p 1.0일 때 16.1%였습니다. |
| DPO 세 차례 | 판독 기준으로 깨진 문장의 총량은 줄지 않았습니다. 3회차에서 기존 유형은 59건에서 39건으로 줄었지만 형식이나 방향에서 벗어난 글이 7건에서 23건으로 늘어, 합계는 66건과 62건이었습니다. |

</Section>

<Section n="04" label="Retrospective">

2회차에서 좋은 출력의 로그확률이 -38.5에서 -64로 내려간 것을 확인했습니다. 3회차에서는 좋은 출력에 대한 손실 항을 더해 -38.4로 유지했지만 총량은 그대로였습니다. 설정마다 무엇이 어떻게 실패하는지를 로그확률과 실패 유형으로 기록했고, 1회차 시점이 도달할 수 있는 지점이라고 판단해 그 상태로 되돌리고 학습을 멈추었습니다.

**한계.** 판정 기준은 한 사람이 세운 것입니다. 그 기준을 문서로 고정하고 가려서 판독하는 절차를 적용했지만, 여러 사람의 판정으로 검증하지는 못했습니다. 평가는 판독 기준에 따른 문장의 성립 여부까지이며, 실제 게시판 이용자가 이 제목을 어떻게 받아들이는지는 측정 범위 밖입니다.

</Section>
