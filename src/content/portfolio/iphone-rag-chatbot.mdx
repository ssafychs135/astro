<Section n="03" label="Defects">

RAG 파이프라인을 처음 만들며 마주친 두 가지 함정입니다. 둘 다 오류 없이 조용히 틀리는 침묵 실패여서, 증상이 아니라 원인을 바이트와 흐름 단위로 파고들어야 했습니다.

  <Grid
    cols={2}
    items={[

      { icon: '🎲', n: 'DEFECT 02', title: '비결정적 검색', sub: '작은 모델의 도구 선택이 흔들림' },
    ]}

  <Defect pnum="DEFECT 01" category="Unicode Hygiene" title="보이지 않는 글자가 검색을 막다">
    <div slot="summary">
      챗봇이 "iPhone 17" 질문에 15와 16 정보만 답했습니다. ChromaDB에는 17 데이터가 분명히 있는데(임베딩은 성공) 메타데이터 필터 결과가 <b>0건</b>이었습니다. 파일명을 눈으로 봐서는 어디가 깨졌는지 보이지 않았습니다.
    </div>
    <ul slot="tech">
      <li>Apple 공식 페이지가 제품명에 <code>&nbsp;</code>(U+00A0)를 사용했고, 크롤러 <code>get_text()</code>가 이를 그대로 가져왔다.</li>
      <li>일반 공백과 픽셀 단위로 같아 <code>print</code>로는 보이지 않았다.</li>
      <li><b>진단</b>: <code>Counter</code>와 <code>repr()</code>로 바이트 수준 키 분포를 출력해 NBSP를 발견했다.</li>
      <li><b>해결</b>: 텍스트가 들어오는 경계에 <code>NFKC 정규화</code>를 적용한 뒤 다시 인덱싱했다.</li>
    </ul>

    <Toggle heading={'질문: "iPhone 17 사양 알려줘"'} labelOff="NBSP 그대로" labelOn="NFKC 정규화">
      <div slot="off">
        <Verdict type="fail">메타데이터 필터 0건, 침묵 실패</Verdict>
        <Kv k="컬렉션 키" v={'iPhone\\xa017\\xa0Pro'} type="fail" />
        <div class="ts-io">답변: <span class="ts-bad">15·16 정보만 응답</span></div>
      </div>
      <div slot="on">
        <Verdict type="ok">필터 정상 매칭</Verdict>
        <Kv k="정규화 키" v="iPhone 17 Pro" type="ok" />
        <div class="ts-io">답변: <span class="ts-good">17 데이터 검색·응답</span></div>
      </div>
    </Toggle>
  </Defect>

  <Defect pnum="DEFECT 02" category="Determinism" title="같은 질문에 매번 다른 답">
    <div slot="summary">
      작은 로컬 모델은 도구 선택이 흔들려, 같은 질문에도 검색 결과가 매번 달랐습니다. <b>결정적인 노드 흐름</b>이 작은 모델의 검색 품질을 더 안정적으로 보장합니다.
    </div>
    <ul slot="tech">
      <li>단일 체인을 <b>LangGraph 8노드 구조</b>로 전환해 노드별 디버깅과 검증을 확보했다.</li>
      <li>도구 호출(자유 선택) 대신 명시적 그래프로 흐름을 고정했다.</li>
      <li>모델 제공 중단에 대응해 Upstage Solar에서 로컬(LM Studio, Gemma)로 이전했다.</li>
      <li>어댑터를 교체하고 임베딩 모델 변경에 따라 전체를 다시 임베딩했다.</li>
    </ul>

    <Toggle heading="검색 흐름 제어 방식" labelOff="도구 호출(자유 선택)" labelOn="명시적 그래프(LangGraph)">
